## 二 · 六步流程

### P0 · 记基线（**必做，回滚和验收都靠它**）


把 `focus_state.json` 里的 `focus_seconds` / `total_seconds` 抄下来。重启后这两个数**只能更大**，变小就是搬错了目录。

### P1 · 停机（用官方脚本，别自己 `Stop-Process`）

```powershell

```

它内部就一句 `taskkill /IM focus_tracker.exe /F`（作者本人设计的停机方式，`FocusLog 3.2.1`）。
**为什么强杀可以接受**：数据是逐行追加的纯文本，`atexit` 只负责删锁文件，不负责 flush 数据。

**验收（两条都要过，否则回到 P1 重来）**：

```powershell

Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*focuslog*' }  # 必须空
```


不清也能跑（启动时发现 PID 已死会自动回收），清了是为了让 `startup.log` 里不出现 `reclaiming lock` 噪音，方便你验收时判断"是不是干净启动"。该文件被 `.gitignore` 忽略（`专注记录/*.lock`），删了不留痕。

## 三 · 唯一会断的地方：自启注册表

`开始记录.bat` 里那句是 `reg add ... /d "%~dp0焦点监控\focus_tracker.exe"` —— **它把绝对路径烤进了注册表**。
所以：

- 搬完**不跑 P4** ⇒ 下次开机 `Run` 项指向 `D:\Desktop\focuslog\...`（已不存在）。Windows 对失效的 Run 项**静默忽略，不报错**，你只会发现"今天怎么一条记录都没有"。
- 这就是本次搬运**最阴的坑**：不是崩溃，是无声失效。

**反向也成立**：如果哪天想回滚，同样只需要再跑一次原位置的 `开始记录.bat`，它会把路径纠正回去。**所以 P4 是全流程唯一的"幂等修复点"，搬家前后各跑一次永远是对的。**
